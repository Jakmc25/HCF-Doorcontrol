# Audit: HCF Door Control 1.0.0 (2026-11-27)

Whole-repo audit at commit b1febf0. Reviewers: code-reviewer (R), security-reviewer (S), qa-tester (Q), release-ops (O).
Existing tests: test_all 23, test_google 60, test_ui 12. All pass; black and prettier are clean.
Overall verdict: CHANGES REQUIRED / release NO-GO.
Duplicates found by more than one reviewer are merged and list every ID.

## BLOCKER
- **S2**, ical.py:82-115, 281-301. Every event in the feed is trusted, including auto-added invitations from outsiders and TENTATIVE events. ORGANIZER and PARTSTAT are never read. An emailed invite "Unlock: ALL" (or "Unlock: e", substring) unlocks doors. Fix: an ORGANIZER allowlist, CONFIRMED events only, a dedicated secondary calendar with invitations off, and no "ALL" / exact names.
- **S1 / R2**, ical.py:164-178 `candidates()`/`_rrule_occurrences`, engine.py tick. `BYMONTHDAY=40` (or 0, 32) loops forever, which was confirmed. Malformed COUNT/INTERVAL raise ValueError outside the per-door try, so the whole tick aborts. Either way the scheduler stops, also after every restart, and unlocked doors stay unlocked. Fix: validate RRULE parts, bound the loop by candidates tried, wrap each event's expansion in try/except and log it, keep calendar errors out of schedule processing, and add a stalled-tick watchdog.
- **Q1 / R1**, engine.py tick and ical.py `load_text`/`fetch_once`. An empty, HTML, garbled or truncated 200 reply, or the startup window before the first fetch, gives zero windows. Calendar-unlocked doors then get locked mid-event, and `last_error` stays None. Fix: keep the last good events unless the feed is a complete VCALENDAR that parses, don't end calendar windows before the first successful fetch, record the window source, and set `last_error`.

## SHOULD-FIX
Door safety and scheduler:
- **Q2 / R3**: calendar door matching is substring, so "Unlock: Main" opens "Main Gate" and "Main Office". Splitting on "and"/"&" breaks names like "Pole Barn and Arena". Unmatched events aren't logged. Fix: exact match, else refuse and log (as `find_door` does).
- **Q3 / R8**: fall-back DST. Wall-clock comparison means a 01:30-01:45 window on 2027-11-07 unlocks twice, and windows ending at 02:00 stay open an extra hour. Spring-forward start times are accepted. Fix: compare in UTC and add DST tests.
- **R4**: RRULE gaps. MONTHLY BYDAY/BYSETPOS ("2nd Tuesday") is ignored, as are BYDAY prefixes (1MO, -1FR). EXDATE;VALUE=DATE never cancels a timed occurrence. An unknown TZID silently falls back, and an unsupported FREQ silently yields nothing. Fix: skip and log rules it doesn't understand, or support them, and compare EXDATE by day.
- **R6**: two ticks can run at once (web `tick_soon` and the loop), which can double-issue UniFi calls. Fix: one tick lock.
- **Q4 / R7**: `end_action` is fixed at window start, so a later overlapping keep_lock window is lost. A non-UniFi exception stops the tick for the remaining doors. Fix: re-evaluate at end time and catch per door.
- **S3**: calendar windows have no maximum length; a daily RRULE with no end keeps doors unlocked indefinitely. Fix: cap at about 16 h and log.
- **R9**: a stale feed never expires, and windows older than the lookback end early. Fix: show "calendar stale" after N minutes and document the all-day behavior.

Access and accountability:
- **S4 / R5**: the Telegram offset starts at 0 and message age is never checked, so queued commands up to 24 h old (e.g. `/unlock`) replay after a restart. Fix: drop messages older than about 2 min, store the offset, and add a per-chat rate limit.
- **S5**: Telegram actions are logged with `user=""`, and calendar unlocks don't record the organizer. Fix: `telegram:<chat_id>` and the ORGANIZER.
- **S6**: sessions are stateless and last 14 days; a suspended Workspace account keeps access. Fix: server-side revocable sessions of about 12 h (Incident Report pattern).
- **S7**: every hardincountyfair.org account (role mailboxes too) can open every door. Fix: named people in `GOOGLE_ALLOWED_EMAILS` and an empty domain list.
- **S8**: with no certificate pin and `verify_tls` false, or an http:// host, the app only warns, so the UniFi bearer token can be intercepted on the LAN. Fix: refuse to start unless the host is https and pinned or verified.

Operations:
- **O3**: nobody is alerted when a door action fails or the scheduler errors. Fix: a Telegram alert to allowed chats after repeated failures or a scheduler error.
- **O4 / R10**: `/health` and the Docker HEALTHCHECK report healthy even when the scheduler thread is dead. Fix: return 503 when the last tick is older than 3 intervals.
- **O1 / R11 (DRIFT)**: no automatic backup of the database, config.json (tokens), accounts or session secret. Fix: daily backup with 14 kept, plus `manage.py backup`.
- **O2**: no Docker log rotation, and the logs hold sign-in emails and IPs. Fix: a compose `logging:` block.
- **O5**: the rollback block copies only the database, not /data/config.json. **O6**: running it twice can replace newer data, and it doesn't check the old service. Fix both in the block.
- **O7 / S10**: the normal deploy block has no backup, no in-block Docker >= 28 check, no healthy wait and no recorded previous commit.
- **O8 / R12 (DRIFT)**: Door Control has no row in dev-standards APPS.md.

## NIT
- **S9**: the log keeps 1000 rows and sign-ins count toward that. Keep rows by age or separate sign-ins.
- **Q5**: each 30 s retry while UniFi is down writes a log row. UniFi timeouts and a 500 on the end-of-window lock are untested.
- **Q6**: Telegram group chats and callbacks are untested; the code ignores them.
- **O9**: the first-move block uses sudo, so it can stop at a password prompt; note this.
- **O10**: container logs are in UTC; optionally set `ENV TZ=America/New_York`.
- **R13**: the version appears in many places; keep to the checklist.

## Untested scenarios (QA)
Q1, Q2, Q3, the overlap cases, a CANCELLED event, UniFi timeouts, the malformed RRULEs (S1/R2) and Telegram replay (S4).
