## Open question: Secure cookies mean no LAN sign-in over plain HTTP

Recommendation: ACCEPT (keep `Secure` cookies, no LAN password sign-in). Reasons: a door-control password and session would cross the fair network in clear text; the Awards pattern (non-Secure LAN cookie) is the weaker one and should not be copied to the app that unlocks buildings. The cost is small: the scheduler and Telegram bot do not depend on the web login, and UniFi's own Access app works on the LAN when the internet or tunnel is down. Make that explicit in README and CLAUDE.md ("if the internet is down, use the UniFi Access app"). Revisit only if the fair gets HTTPS on the LAN.
